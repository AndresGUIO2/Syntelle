## Go scope and project overrides

These six skills guide `services/api`, including the entry point in `cmd/api`, HTTP/access/lifecycle code in `internal/httpapi`, conversation orchestration in `internal/conversation`, and voice adapters/ledgers in `internal/speech`. Follow [Go service organization](go-service.md). Select skills by the behavior being changed; read linked references as needed. Vue and Python retain their own skills. References to other Go skills do not authorize recursively installing the upstream collection.

The following Syntelle rules explicitly supersede conflicting defaults in `samber/cc-skills-golang`:

- Preserve Vue on Cloudflare, separate Go and FastAPI services on Azure Container Apps, and Azure Speech recognition/TTS with native visemes. Current Gemini/explicit historical adapter selection remains governed by [local conversations](local-conversations.md). Skills do not select another provider, transport, cloud or model.
- Keep the small Go service, `net/http`, pinned `coder/websocket`, `pgx` and explicit constructor/interface wiring. Add a library or layer only when the authorized task requires it. Recommendations for `gotests`, `testify`, `goleak`, `samber/oops`, alternative SQL clients or DI frameworks are not installation requirements. Do not run upstream `@latest` installation commands automatically.
- Use PostgreSQL and preserve complete provider input/result records and immutable evidence. Commit operation/input records before paid calls. Preserve historical budgets and cache eligibility; current local-owner conversation/Read aloud remains uncapped at application level, with existing per-message bounds. Do not reinstate historical trial ceilings. Other experiment allowances remain separate and authoritative.
- Preserve no-fallback/no-automatic-paid-retry and stopped-provider rules. Generic retry examples do not authorize provider calls, regeneration, model substitution or budget resets.
- Propagate cancellation for interactive work. A narrowly bounded final database/evidence write may deliberately outlive request cancellation, as in the existing implementation. `context.WithoutCancel` or a goroutine does not provide durable job execution on a scale-to-zero service; public preparation dispatch remains a separate architecture decision.
- Keep verification bounded to changed behavior. Use local provider fixtures by default; tests do not authorize paid calls. Integration fixtures must construct and verify an isolated test database before mutation, never reuse preparation, speech or conversation evidence databases. Do not replace visual evidence or rerun historical preparation/finalization commands for a Go change.
- Use scoped implementation/review by default. Upstream broad-audit and parallel-agent modes do not turn a small task into a full-codebase audit; follow requested scope and applicable agent instructions.
- The database skill's blanket prohibition on schema/migration authoring does not override an explicitly authorized Syntelle schema task. Follow project requirements, isolation and review for that task; this installation adds no schema/migration. Internal error-format conventions must preserve established user-facing messages unless changing them is part of the task.
- Preserve loopback-only owner access, personal/work credential separation and server-side keys. Logs must not expose credentials or raw microphone PCM; structured evidence remains governed by current persistence policy. Installation does not authorize public access or deployment.
